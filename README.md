# MindSurf Omni

语音 AI 产品的算法侧。这是训练组的交付仓库。

**现在的产品是听写**：说话 → 转写 → 润色 → 注入文本框。
第四次会议（2026-08-14）之后定的，问答助手和「混合」模式已经移除。
读数在 [§2](#2-指标)，接法在[接入指南 §5.5](docs/INTEGRATION.md#55-听写链转写--润色)。

## 这东西的位置

不是「最准的听写」。是**同等参数下做得出来的那个产品**：

- 识别 SenseVoice-Small 234M，润色 139M，**合计 373M**——笔记本上跑得动，
  不联网，不上传录音
- 4090 上 13.8 秒口述整轮 **198 ms**，人感觉不到延迟
- 中间那一级**别人没有**：受复制约束的口语词清除。解码被限制成
  「输出必须是转写的子序列」，所以它删得掉「嗯、那个、就是」，
  却在结构上加不了字——编造这一格是被架构压住的，不是被调参压住的

同参数级的对手是 Whisper small（240.6M，也是 MacWhisper / superwhisper /
whisper.cpp 的默认选择）。同一批音频、同一台 4090、同一个口径：

| | 参数 | 字错率 | P50 | 峰值显存 |
| --- | ---: | ---: | ---: | ---: |
| AISHELL-1 test 400 条 | | | | |
| Whisper small | 240.6M | 0.1333 | 100 ms | 1403 MB |
| **SenseVoice-Small** | 234.0M | **0.0614** | **52 ms** | **944 MB** |
| 真人自发口述 60 段 | | | | |
| Whisper small | 240.6M | 0.3088 | 414 ms | 1403 MB |
| **SenseVoice-Small** | 234.0M | **0.1903** | **56 ms** | **1044 MB** |

**限制**：两批都是中文，Whisper 是多语种通才、在中文上本来吃亏；
英文侧我们没有带参照的语料，没量，这两张表不许读成「全面更好」。

而 Whisper 只转写，不清口语词。清口语词的产品（Wispr Flow、Gboard 的 Rambler）
都在云上跑大模型。**本地 + 小 + 带润色，这三样同时成立的，我们没找到第二个。**

语言：识别支持 zh / en / yue / ja / ko；润色中文靠模型、英文靠规则、
其余原样通过。「不支持」和「弄坏」在判据里是分开的两件事，
见 [`headline_numbers.json`](configs/release/headline_numbers.json) 的
`dictation_multilingual`。

在此之前做的是端到端语音助手，模型内部把音频当作一种语言，
音频 token 与文本 token 在同一条自回归序列里。那部分没有删，也没有作废：
延迟、打断、音色克隆三项都做完并量过，口径是**已验证、按数据选择不投产**。
证据留在下面、[接入指南](docs/INTEGRATION.md)和 [`artifacts/`](artifacts) 里，
因为它们是做过并且量过的东西。

### 听写（现在的产品）

986 条留出集，RTX 4090 上的服务真路径。
**这几条线是算法侧自拟的工作标尺，不是小组 OKR 的验收线。**

| | 值 | 不润色时 | 自拟线 | 重抽里落在线内侧 |
| --- | ---: | ---: | --- | --- |
| 口语词清除 | **0.9722** | 0 | ≥ 0.90 | 100% |
| 空输出 | **0** | 0 | 0 | — |
| 内容保留 | **0.9803** | 0.9868 | ≥ 0.98 | 62% |
| 编造 | **0.0199** | 0.1054 | ≤ 0.02 | 54% |
| 与原文的字错率 | **0.0269** | 0.1060 | ≤ 0.02 | **0%** |
| 整轮延迟（13.8 秒口述） | **P50 198 ms / P95 204 ms** | — | — | — |
| 建议在飞上限 | **8 路** | — | — | 吞吐 97% 峰值，P95 860 ms |

**「过线」按重抽比例读，不按点估计。** 配对自助 4000 次里，
内容保留只有 62%、编造只有 54% 落在线内侧。这两条是和线分不清，不是过了。
清除和空输出是稳的。字错率明确没过。

字错率没过的构成：0.0269 里 0.0127 是识别器听错的字（润色器被约束成只能删，
改不了），0.0041 是把语料自己的口语词也删了（对听写产品是对的）。
两项相加 0.0168 是这套架构在这把尺子上的地板，地板在线以下。

## 3. 边界

### 听写

1. **字错率没到自拟的 0.02。** 0.0269，重抽里一次都没落在线内侧。
   可达的还剩约 0.010，要过线得吃掉其中七成。那要重训一轮，
   合并层面的杠杆已经拉完了。
2. **内容保留和编造贴在线上。** 0.9803 和 0.0199 看着都过，
   但重抽里只有 62% 和 54% 落在内侧。换一批句子重跑可能掉到线外。
3. **识别器听错的字改不了。** 润色被约束成只能删，「客户那边」听成
   「客户拿边」这类错一个都纠不了，占字错率的 47%。换来的是编造那一格
   被结构性地压住，是知情取舍。
4. **短于 1.5 秒的音频，语言判定不可靠。** 半秒的「嗯」会被判成日语。
   现在的做法是短音频用部署声明的语言（`MINDSURF_ASR_LANGUAGE`，默认 `zh`），
   长音频照旧自动判。这不是让模型变准了，是绕开了它不准的那一段。
5. **噪声还是会冒字。** 45 段合成噪声里 22 段出字：半秒的白噪、粉噪、
   工频嗡、人声嘈杂全部写成 `嗯。`，两秒的键盘敲击写成 `The.`。
   语速那道闸放过了半秒以下的（那个长度上算不出速率），也放过了压线的
   `The.`（1.5 字/秒）和 `我。`（正好 0.50）。
   **对话那一侧已经挡住了**（整条转写只剩一个口语词字时不回复），
   所以「按错录音键，模型念一段话」闭环了；听写那一侧的文本框里还是会多两个字。
   试过在识别器出口按帧能量的变异系数挡，量下来不能用：稳态噪声最高 0.364，
   而会议室免提的真语音（混响+带限+压缩）最低 0.232，两个分布重叠，
   没有一个阈值能同时安全又有用。
6. **热词够不着声母不同的。** `李欣` 对 `吕鑫`、`林犀` 对 `灵犀`，
   无声调拼音也不同音。放宽到前后鼻音实测更差。
7. **长录音的分段是在合成语音上调的。** 停顿分布是合成器的不是人的，
   90 秒那个拐点在真人录音上可能会动。仓库里没有真人录音可以验。
8. **松开后的等待仍随录音长度增长。** 分段把它从线性压到了亚线性
   （900 秒 4263 → 1861 ms），但要变成常数（约 55 ms）需要客户端边录边送，
   那一侧还没做。
9. **没有客户端。** 产品定义是「按住说话 → 松开 → 文本进输入框」，
   后半句一个字都没实现——仓库里 grep `clipboard|hotkey|paste` 零命中，
   只有 `examples/minimal_client.py`（httpx 调 API）。对标下来这也是同类产品
   故障率最高的一面（Citrix / RDP / VMware / 银行应用 / 终端各有各的坏法）。
10. **热词够不着两类。** 声母不同的（`李欣` 对 `吕鑫`）；以及分词器把它读成
    几个正常词的（句首的 `通一千问` 切成 `通/一千/问`）。解码期偏置能治第一类，
    实测下来不划算：召回 8/9 → 9/9，但陷阱改坏 1/10 → 3/10、慢四倍、没有标点。
11. **真人自发语音上，润色删得比留出集显示的多。** 60 段真人口述
    （MagicData-RAMC，人工转写）过整条链：转写 5252 字，删掉 354 字（6.74%），
    而删除单位里只有 16.4% 的字在口语词表内、21.8% 是去掉一份重复，
    **剩下 61.9% 两样都不是**。那 61.9% 里有相当一部分是口语词串
    （`那个怎么说呢`、`就是那那个那个`），但也有真删了内容的：

    ```
    听成 …你咱们学校是不是还有一个宗教信仰那那那社团了？
    出来 …学校是不是还有一个宗教信仰社团了？        ← 「咱们」跟着「你」一起没了
    听成 我感觉就是这个西方人是我感觉他想象力也特别强
    出来 我感觉这个西方人是我想象力也特别强          ← 「感觉他」被删，句子读不通
    ```

    **986 条留出集看不见这一格**：那里的口语词是我们自己按概率插进去的，
    而真人是把口语词和实词绞在一起说的。这是目前最该继续量的一条。

### 语音助手

具体看[训练说明 §4](docs/TRAINING.md#4-结果与边界)。

1. **把回复变短之后，没法证明对话能力没跟着退。**
   不是退了，是测不出来——衡量对话能力的办法本身也在衡量长度。
   四种办法都试过，要测得准约需 3600 条测试提问，我们有608条。
2. **情绪能力存在，但做不到「只动情绪、不动身份」。**
   换一条带情绪的参考，输出就带情绪；但那条参考同时决定说话人是谁。
3. **打断做到了执行，没做到判断。**
   调用方说停就真停，但「什么时候该停」缺语料，两份训练语料都没有重叠音频。

## 5. 怎么复测

逐条读数都在 [`artifacts/`](artifacts)，不用重跑训练。

```bash
uv sync --extra dev --extra tts

# 语音：CER、UTMOS、静音率，以及对父模型的逐条对照
python scripts/evaluate_speech.py \
  --candidate artifacts/merge/speech-sft_merge-mos.jsonl \
  --reference artifacts/merge/speech-parent-mos.jsonl

# 人工盲听（读 xlsx 要 openpyxl）
uv sync --extra listening
python scripts/listening_test.py score \
  --pack artifacts/listening_returned/listening_models \
  --key artifacts/listening_models/key.json

# 听写：986 条留出集走服务真路径
python scripts/measure_polish_service.py   --pairs artifacts/polish_train/pairs_holdout.jsonl   --checkpoint out/sft_polish6_768.pth --minimind-root ../minimind-o   --tagger out/polish_tagger_unionchar.pt   --tagger-backbone out/polish_tagger_unionchar_backbone.pth   --tagger-threshold 0.4 --device cuda

# 自检
.venv/Scripts/python -m pytest -q
python scripts/verify_delivery.py
```

盲听那条会打出两组数，因为有两种算平均的办法，**我们对外报的是第一种**：

| 办法 | 我们的成品 对 官方 |
| --- | --- |
| **逐条评分平均**（每一条打分各算一次） | **2.738 对 2.738** |
| 按片段均值再平均（每条片段各算一票） | 2.731 对 2.737 |

两个数不一样不是舍入。盲听包里故意混了重复片段，用来查评分员自己前后状况是否发生变化，
所以每条片段被打分的次数不等（有的五次有的四次）。
按片段那种算法会把听的人少的片段和听的人多的算成一样的加权。
**我们平均的是人的判断，不是片段的质量，所以每条打分各算一次。**
参照上限 edge-tts 是 4.023。

对话盲评要打分模型的 API key，命令和逐对判词在
[`artifacts/blind608/`](artifacts/blind608)。换一个打分模型重判如果结论不同，
那不代表旧数字错了，代表这个结论取决于用哪个模型来判。

**别用 `uv run pytest`**：dev 依赖是 extra 不是 group，`uv run` 不装它。
