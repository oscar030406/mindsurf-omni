# MindSurf Omni

按住快捷键说话，松开，一段干净的文字出现在输入框里。
这个仓库是这件事的算法侧，训练组的交付仓库。

整条链只做三件事：把语音转成文字（SenseVoice-Small，官方原生模型）；
把转写里的「嗯、那个、就是」这类口语词删掉（我们自己训练的润色器，仓库的主体）；
用户点小喇叭的时候把文字念出来（edge-tts，默认关着）。不点就不出声。

读数在 [§3](#3-指标)，怎么接在[接入指南](docs/INTEGRATION.md)，
润色器怎么训的在[训练说明](docs/TRAINING.md)。

## 定位

- 识别器 SenseVoice-Small 234M，润色器 139M，合计 373M。
  笔记本上跑得动，不联网，录音不出本机。
- 4090 上一段 13.8 秒的口述，从松开到文字出来 198 毫秒，用户感觉不到等待。
- 解码时模型只被允许把转写里的字保留或删掉。
  不允许写出转写里没有的字。

## 1. 链路

```text
麦克风 ─► SenseVoice 转写 ─► 润色（删口语词）─► 文本框
                                  │
                                  └─► 点小喇叭：edge-tts 念一遍
```

润色这一级是两个互相独立的模型在同一份转写上各删各的，然后合并：
一个生成式模型（被锁成只能删字），一个逐字打分的标注器。合并规则是两边都
说删才删，只有两类例外（词表里的口语词、紧挨着的整段重复），这两类一边认出来
就删。生成式擅长口语词，标注器擅长重复，强项刚好不重合。

部署时想确认标注器接没接，看 `/health` 的组件表里有没有 `polish-tagger`，
配漏了服务照样正常应答，只是删得少。

两个入口，同一条链，出来的文字逐字相同：

| 入口 | 什么时候用 | 说话期间 |
| --- | --- | --- |
| `POST /v1/audio/transcriptions` | 录完再送 | 不出字 |
| `WS /v1/realtime` | 流式 | 每秒刷一次预览 |

## 2. 产物

听写要三份权重：

| 文件 | 干什么 |
| --- | --- |
| `sft_polish6_768.pth` | 生成式那条臂，被约束成只能删 |
| `polish_tagger_unionchar.pt` | 逐字标注器，第二条臂 |
| `polish_tagger_unionchar_backbone.pth` | 标注器的骨架 |

识别用官方原仓库的 SenseVoice-Small，朗读用 edge-tts，两个均无做修改。

| | 地址 |
| --- | --- |
| 代码、文档、逐条证据 | 这个仓库 |
| 权重、tokenizer、配置 | [`oscar0403/mindsurf-omni`](https://huggingface.co/oscar0403/mindsurf-omni) |

**vLLM。** 同一份权重挂上 vLLM、带着复制约束，能跑到进程内实现的 10.3 倍
（37768 对 3678 含 prompt tok/s，256 条输出无一例外仍是转写的子序列）。
但换推理后端是部署的决定，不是内核的一部分。本仓库只提供论据和一份能直接跑的实现
（`scripts/vllm_copy_constraint.py`）。按现在的量级其实用不上：进程内整轮
10.14 轮/秒，一轮约 14 秒语音，一张 4090 够约 140 个人同时不停地口述。vLLM
真正改变的是高并发下的延迟形状：我们的 P50 随并发线性变差（472 → 2622 ms），
而vllm里几乎是平的（368 → 384 ms）。并发真上来了再考虑。

## 3. 指标

986 条留出集，读数取判据可信的那 377 行（下面解释）。

| | 值 | 不润色时 | 自拟线 | 重抽里落在线内侧 |
| --- | ---: | ---: | --- | --- |
| 口语词清除 | **0.9606** | 0 | ≥ 0.90 | 100% |
| 空输出 | **0** | 0 | 0 | — |
| 内容保留 | **0.9873** | 0.9868 | ≥ 0.98 | 100% |
| 编造 | **0.0175** | 0.1054 | ≤ 0.02 | 94% |
| 与原文的字错率 | **0.0198** | 0.0460 | ≤ 0.02 | **56%** |
| 整轮延迟（13.8 秒口述） | **P50 198 ms / P95 204 ms** | — | — | — |
| 建议并行路线 | **8 路** | — | — | 吞吐 97% 峰值，P95 860 ms |

最后一列：把行反复重抽 4000 次，每次重算一遍指标，看它有多少次仍落在线内侧。
字错率点估计在线内但重抽只有 56%，正确的说法是「和线分不清」，不是「过了」。

为什么只取 377 行。留出集的口语词是我们按九个词等概率插进去的，其中七个是
两栖词（那个、这个、就是……），而它的 target 是把九个词全拿掉的干净文本——
于是「那个模块」里的「那个」也被标成该删。产品后来学会了不删这一类，判据反而
因此扣它的分，而且三条判据同时扣：留一个字，字错率记一次删除错、编造记一个
多余字、口语词清除记一次没清掉。剩下 609 行都带这种注入，那一半量的是对注入器
的服从，不是正确性，所以分开报：

| | 判据可信的 377 行 | 目标要求删内容词的 609 行 |
| --- | ---: | ---: |
| 与原文的字错率 | 0.0198（润色前 0.0460） | 0.1008（润色前 0.1431） |
| 编造 | 0.0175 | 0.0967 |
| 内容保留 | 0.9873 | 0.9811 |

609 行那一列不是失败，是判据在罚一个正确的行为——同一批修复让 20 段普通听写
从 0/20 被改坏变成 18/20 正常。

口语词清除按标签可信的那部分算（嗯、呃、你知道吧、怎么说呢、对吧，加上重复的
内容词）。两栖词那一桶单独报是 0.1090，故意不删。全部 986 行的合并值是 0.4333，
七成到达量是两栖词，这个数会被它们主导，不适合当判据。

留出集的口语词是我们自己插进去的，所以另外拿 230 段真人长口述（RAMC）再量一遍。

| | 产品（两条臂） | 只有生成式 | 真人编辑 |
| --- | ---: | ---: | ---: |
| 嗯/呃 删掉 | **0.9902** | 0.7781 | 0.9835 |
| 整段重复删掉 | 0.8889 | 0.5881 | 0.9296 |
| 没理由的删除（每千字） | **11.57** | 29.2 | 37.99 |
| 否定词存活 | **0.9982** | — | — |

## 4. 边界

1. 识别器听错的字改不了。润色只能删，「客户那边」听成「客户拿边」这类错一个
   都纠不了，占字错率的 47%。换来的是编造被结构性压住，这是一笔值得的交换。
2. **删口语词时会连着吃掉旁边的内容字。** ：
   「就是我们那个那个会议」出来是「就是我们会议」（该删的删了，留下的话不通）；
   「就是说需要发票」出来是「说需要发票」。
3. **真人自发语音上删得比留出集显示的多。** 60 段真人口述过整条链：转写 5252
   字，删了 354 字（6.74%）。删掉的字里只有 16.4% 在口语词表内、21.8% 是去掉
   一份重复，剩下 61.9% 两样都不是。里面有口语词串，也有真删了内容的：

   ```text
   听成 …你咱们学校是不是还有一个宗教信仰那那那社团了？
   出来 …学校是不是还有一个宗教信仰社团了？        ← 「咱们」跟着「你」一起没了
   听成 我感觉就是这个西方人是我感觉他想象力也特别强
   出来 我感觉这个西方人是我想象力也特别强          ← 「感觉他」被删，句子读不通
   ```
  
4. 短于 1.5 秒的音频，语言判定不可靠：半秒的「嗯」会被判成日语。现在短音频
   直接用部署声明的语言（`MINDSURF_ASR_LANGUAGE`，默认 `zh`），长音频照旧自动判。
5. 噪声还是会冒字。45 段合成噪声里 22 段出了字：白噪、粉噪、工频嗡、人声嘈杂
   全写成「嗯。」，键盘敲击写成「The.」。试过按帧能量的变异系数在识别器出口
   挡，量出来不能用：稳态噪声最高 0.364，会议室免提的真人语音最低 0.232，两个分布重叠.
6. 热词够不着两类：声母不同的（「李欣」对「吕鑫」，无声调拼音也不同音），
   和被分词器读成几个正常词的（句首的「通一千问」切成「通/一千/问」）。
   解码期偏置能治第一类，实测不划算：召回 8/9 → 9/9，但陷阱句改坏
   1/10 → 3/10、慢四倍、还丢标点。
7. 长录音的分段参数是在合成语音上调的，停顿分布是合成器的不是人的，90 秒
   那个拐点在真人录音上可能会动，仓库里没有真人长录音可验。松手后的等待仍随
   录音长度增长，分段把它从线性压到了亚线性（900 秒从 4263 降到 1861 ms），
   要变成常数（约 55 ms）需要客户端边录边送。
8. **流式预览只在「一个人对着麦克风口述」这个场景上成立。** 四段听写
   上显示的文本逐字等于最终转写；同一套测试放到双人对话上，八段零段一致，
   p90 有 50 个字被改写。抢话、重叠、改口会让识别器反复改主意。

## 5. 许可

**当前产出物不可商用。** 文本基座继承训练数据的 CC-BY-NC-4.0，并传导到所有
微调结果。`GET /v1/models` 会在响应里带 `commercial_use_permitted: false`，
让这件事没法被忽略。
朗读走 edge-tts，是托管服务：要念的文本会离开本机。所以它默认关着。

## 6. 怎么复测

逐条读数都在 [`artifacts/`](artifacts)，不用重跑训练。

```bash
uv sync --extra dev

# 听写：986 条留出集
python scripts/measure_polish_service.py \
  --pairs artifacts/polish_train/pairs_holdout.jsonl \
  --checkpoint out/sft_polish6_768.pth --minimind-root ../minimind-o \
  --tagger out/polish_tagger_unionchar.pt \
  --tagger-backbone out/polish_tagger_unionchar_backbone.pth \
  --tagger-threshold 0.4 --device cuda

# 长口述：230 段 RAMC，不需要人工标签
python scripts/measure_group_length.py \
  --data artifacts/polish_train/pairs_long.jsonl --split val --lengths 1 \
  --checkpoint out/sft_polish6_768.pth --minimind-root ../minimind-o \
  --tagger out/polish_tagger_unionchar.pt \
  --tagger-backbone out/polish_tagger_unionchar_backbone.pth

# 识别器对标
python scripts/measure_recogniser_bench.py --help

# 四道交付闸
python -m pytest -q
python scripts/verify_delivery.py
python scripts/release_gate.py --range origin/main...HEAD
python scripts/smoke_service.py --base http://localhost:8000   # 需要服务在跑
```

两个容易踩的坑：别用 `uv run pytest`（dev 依赖是 extra 不是 group，`uv run`不装它）

## 7. 仓库地图

```text
src/mindsurf_omni/
  service/     推理服务：识别、润色、装配、HTTP 与 WebSocket
  data/        造训练数据用的合成器
  evaluation/  字错率等判据
scripts/       训练、评测、复现用的命令行工具
tests/         契约与仪器的回归
configs/       release/ 下的模型卡与数字来源
artifacts/     每个数字的逐条读数（音频与权重不入库）
docs/          两份正文：接入指南、训练说明
assets/        tokenizer
examples/      客户端
```

`configs/release/` 下那两份 `*_CARD.md` 是 Hugging Face 两个仓的 README。

上游：[预训练仓库](https://github.com/io-wy/MindSurf/tree/pretrain)（基座）、
[MiniMind-O](https://github.com/jingyaogong/minimind-o)（模型架构，Apache-2.0）、
[SenseVoice-Small](https://huggingface.co/FunAudioLLM/SenseVoiceSmall)（识别器）。
