# 接入指南

写给推理后端和前端。不需要读训练代码，本文件加上
[`contract.py`](../src/mindsurf_omni/contract.py) 就够了，两者冲突以代码为准。

**接之前先看 [§0](#0-接之前必须知道的四件事)。** 那四条决定了用户觉得这套东西好不好用，
每一条都有量出来的依据，而每一条都能在接线时被无意中踩掉。

---

## 0. 接之前必须知道的四件事

**一、默认走级联，不要默认走原生。**
原生路径验收过，首音 145 ms 比级联快一个数量级，但它的声音明显更糙：
自己发音 CER 0.0962、人耳 MOS 2.738；级联走 edge-tts 是 CER 0.0359、MOS 4.023。
「与上游官方发布权重无法区分」说的是我们和上游打平，不是说好听——
2.738 在 1 到 5 的刻度上落在「费力」和「可以接受」之间。
自然度那道差距里 79% 是编解码器不是模型，所以换个 Talker 也救不回来。
**原生是能力证明和延迟储备，级联是现在该端给用户的那条。**

**二、12 个音色只投放 6 个。**
`arthur`、`serena`、`eric`、`uncle_fu`、`dylan`、`moon` 的 12 选 1 认人是 19–20/20；
`cherry`、`ethan`、`chelsie`、`momo` 只有 ≤ 2/20，塌向 serena 和 moon。
把它们摆进选择器，用户切了听不出区别，会当成 bug 报回来。
`vivian`、`jennifer` 是 8–15/20，要用先自己听。名单见[能力边界 §2.4](CAPABILITIES.md)。

**三、原生路径的情绪不是旋钮。**
契约里有 `emotion` 字段，级联三档照常用。原生这边只能「换一条带情绪的参考」，
而那条参考同时决定身份——**没法在不换人的前提下把「开心」调大一点**。
前端要做情绪滑块，只能挂在级联上。理由见[能力边界 §3](CAPABILITIES.md)。

**四、判断用户是否插话，是客户端的活。**
模型说停就真停（取消到停 P50 0.26 ms，GPU 半秒内归零），但「谁判断该停」我们没有做，
缺的是重叠音频加打断标注的语料。端点决定在客户端，契约就是这么定的。

## 2. 许可

`GET /v1/models` 的响应里带着结论：

```json
{ "licence": "CC-BY-NC-4.0", "commercial_use_permitted": false }
```

结论背后的链条在 `GET /v1/licence`。八项资产里有四项的 `commercial_use` 是 `null`：
MiniMind-O 的训练数据、上游 Talker 权重、SenseVoice、emotion2vec。
**`null` 不是 `false`。** `false` 读起来是「查过、不许」，而这四项是「读了但答不了」
或者「声明本身互相矛盾」。要判断能不能发某个东西，你需要看见这个区别。

核实过的四项：文本基座 CC-BY-NC-4.0（不可商用，这条是绑定约束）、
MiniMind-O 代码 Apache-2.0、`mimi` CC-BY-4.0（可商用，必须署名，署名对象已钉 revision）、
`campplus` Apache-2.0。

`model/SenseVoiceSmall` 里那份 README 自称 Apache-2.0 是错的，权威卡片是 `license: other`。
**别拿副本对自己许可的声明当依据。**

权重继承训练数据的许可并传导到所有微调结果，所以当前产出物默认不可商用。
这条不是只写在文档里，它跟着每一个响应走。

## 3. 协议：OpenAI 兼容

不发明新协议。这样你可以把已有客户端直接指过来，
也可以在我们的模型不稳时立刻指回托管服务做对照。那个退路比任何自研协议都值钱。

| 端点 | 用途 |
| --- | --- |
| `POST /v1/audio/transcriptions` | 语音转文本 |
| `POST /v1/chat/completions` | 文本对话，`stream=true` 走 SSE |
| `POST /v1/audio/speech` | 文本转语音 |
| `GET /v1/models` | 当前路径、组件身份、许可 |
| `GET /v1/voices` | 可用音色 |
| `GET /v1/token-spec` | 特殊 token 规格（机器可读） |
| `GET /v1/licence` | 完整许可链，含尚未核实的那几项 |
| `WS /v1/realtime` | 端到端流式语音 |
| `GET /health` | 就绪度，逐部件；降级返回 200，全不可用才 503 |

### 音频格式写死，不协商

| 方向 | 格式 |
| --- | --- |
| 上行 | PCM16 / 16 kHz / 单声道 |
| 下行 | PCM16 / 24 kHz / 单声道 |

重采样服务端做。客户端不需要判断该用哪个采样率，需要判断就会有人判断错——
而采样率错了不是没声音，是声音变调，用户会报「模型听起来怪怪的」而不是报 bug。

`POST /v1/audio/speech` 的响应带 `X-Sample-Rate` 和 `X-Encoding` 头，别硬编码。

## 4. WebSocket 实时链路

事件名沿用 OpenAI Realtime API 的子集，不用学新词汇。

```javascript
const ws = new WebSocket("ws://localhost:8000/v1/realtime");

// 连上先收 session.created，里面有采样率，按它走
ws.onmessage = (event) => {
  const message = JSON.parse(event.data);
  switch (message.type) {
    case "response.text.delta":  appendText(message.delta); break;
    case "response.audio.delta": playPcm(atob(message.audio)); break;
    case "response.done":        turnFinished(); break;
    case "error":                console.error(message.error.message); break;
  }
};

// 边说边发
ws.send(JSON.stringify({ type: "input_audio_buffer.append", audio: base64Pcm }));
// 说完
ws.send(JSON.stringify({ type: "input_audio_buffer.commit" }));
// 打断
ws.send(JSON.stringify({ type: "response.cancel" }));
```

音频是边生成边下发的，不是等整段做完。收到第一个 `response.audio.delta` 就可以开始播——
这正是延迟预算里最大的一项，等整段会把整个生成时间都花在用户听到之前。

不认识的事件会收到 `error` 而不是被忽略。静默会让你一直等一个永远不来的回复。

### 上下文会被裁剪，而且它会告诉你

`response.done` 带 `context`：

```json
{ "type": "response.done", "context": { "turns": 4, "used_tokens": 820, "budget": 2560, "dropped_turns": 2 } }
```

音频是吃上下文的大头。Mimi 每秒 12.5 帧，十秒语音就是 125 个 token，
几轮下来序列比模型见过的还长。所以历史会被裁，而且从最旧的一端裁：
丢掉最新一轮会让模型回答一个刚才没人问的问题，那读起来像模型坏了而不像上下文满了。

`dropped_turns > 0` 时你应该知道，因为悄悄变短的历史正是「模型莫名其妙失忆」的样子。
换一个使用者时发 `session.clear`，把上一个人的历史带进下一段对话比丢掉更糟。

多轮只测到三轮：不崩、上下文利用 82% 且不衰减，
但答得上的比例随深度掉（42%、24%、14%）。十轮以上没测。

## 5. 两条路径

```
                 ┌── native   端到端，音频 token 直接过模型，不经过文本
/v1/realtime ────┤
                 └── cascade  语音识别 → 文本 → 语音合成
```

切换是服务端配置。调用方分辨不出是哪条在答，除非去问 `GET /v1/models`，
那里如实报 `"path": "native" | "cascade"`。

两条都做是有意的：139M 规模能否把中文说好没有先例，
而级联已被姊妹项目实测到端到端 P95 1.93 秒。产品不能只有一条能出声的路。
哪条该默认见 [§0](#0-接之前必须知道的四件事)。

**做质量报告时务必带上 `path`。** 不说明哪条路径答的报告，什么也没测。

## 6. 情绪与音色怎么传

情绪走独立字段，不要塞进文本：

```json
{ "input": "今天天气真好", "emotion": "happy" }
```

塞进文本的后果是模型可能把指令念出来。姊妹项目踩过：情绪指令前缀被合成器偶发朗读。

音色走 in-context voice cloning，参考音频作为条件，不是微调权重。
换音色只换参考音频，权重不动，加一个音色不需要训练。
模型侧收 `spk_emb` 和 `ref_codes`，12 个音色现成；
服务侧要把选中的音色喂进推理调用，**并且只投放 §0 第二条那 6 个**。

## 7. 推理参数：文本能调，音频不能

### 7.1 先看这条，它不是参数是选权重

级联的 `MINDSURF_THINKER` 和原生路径可以共用同一个 checkpoint。
**指向哪个由 [`headline_numbers.json`](../configs/release/headline_numbers.json) 的
`delivery.checkpoint` 说了算**，现在是 `sft_merge_768.pth`。
指错了服务照样起、`/health` 照样 ready，没人从外面看得出来——服务器上那个启动脚本
就曾经写死过一个被取代两代的名字。

下面这张表是 2026-07-30 那一轮的证据，它证明的是**级联该用一个没付 A2A 代价的 Thinker**：

| | `t2a_graft` | `sft_graft`（当时现状） | `sft_mindsurf` | 上游发布 |
| --- | ---: | ---: | ---: | ---: |
| 中立参照集 `chat_nll`（低者优） | 3.8596 | 5.4137 | 3.9731 | 4.2184 |
| 盲评多数票（对 `t2a_graft`） | | 输 74% | 输 62% | 未测 |

盲评是同 158 条提问各自作答、左右随机、判官不知道谁是谁，三个维度分别判；
长度和位置偏差都查过都不成立，而且位置偏差方向是帮现状那一臂的。
中立参照集有两个（上游写的、外部写的），在这一条上一致。

冻结 Thinker 重跑 A2A 之后，`sft_graft_frozen` 的 Thinker 逐位等于 `t2a_graft`（91/91），
所以它在文本上就是这张表里最好的那一列，同时带着通过验收的 Talker，两条路径因此收敛到一个 checkpoint。

**`sft_merge` 是在它之上再加两次 DPO 的权重差**，中位回复从 26.0 秒降到 11.8 秒。
上面这条级联建议**没有在 `sft_merge` 上重跑过**，所以这里不改结论：
要拿 `sft_merge` 跑级联（默认就是它），文本质量请自己量一次再下判断。

有一条没变：**原生路径要同一个 checkpoint 里配套的 Talker。**
`t2a_graft_768.pth` 不能拿去跑原生，它的 Talker 从没在那个位置见过说话人 token，
克隆 240 条里只出得来 3 条。加载器会检查参数量与缺失张量，设错会拒绝而不是静默降级。

### 7.2 `temperature` 和 `top_p` 只作用于文本

它们碰不到音频。提高 temperature 期待「语音更有表现力」，
会得到完全一样的音频和更飘的文本。

| 轴 | 参数 | 值 | 谁定 |
| --- | --- | ---: | --- |
| 文本 | `temperature` | 0.7 | 你调（契约默认，`contract.py`） |
| | `top_p` | 0.9 | 你调 |
| | `max_tokens` | 512 | 你调 |
| | 重复惩罚 | 1.0（关） | 写死，`native.py`，文本不加惩罚 |
| 音频 | temperature | 0.2 | 写死在上游 `stream_generate` 里 |
| | `top_k` | 50 | 写死 |
| | 重复惩罚 | 1.05 / 最近 3 码 | 写死 |

### 7.3 音频那三个值不要动，理由是扫过了

在上游官方权重上扫（能让好模型变好的设置才值得留），7 组交替轮转、每组 24 条：

| 设置 | CER 均值 | 配对判定 |
| --- | ---: | --- |
| 继承 t0.2 / k50 / rp1.05 | 0.0611 | |
| t0.2 / k50 / rp1.2 win8 | 0.0542 | 无法区分（−0.0069，±0.0471） |
| t0.2 / k200 | 0.0658 | 无法区分 |
| t0.5 / k50 | 0.0735 | 无法区分 |
| t0.2 / k5 | 0.0957 | 无法区分 |
| 近贪心 t0.05 | 0.1146 | 无法区分 |
| 去掉重复惩罚 | 0.1505 | 无法区分（+0.0894，±0.2281） |

没有一组打得过继承值，也没有一组被证明更差。逐码本温度又扫了两个方向
（cb0 贪心、深层贪心，各 160 条配对），CER 与 UTMOS 全部无法区分，
而且是有资格的无法区分（配对能分辨 0.031 到 0.048，关心的效应 0.05）。

**那个重复惩罚不是装饰，别当死代码删掉。** 去掉它有三条样本炸掉，
逐例 CER 0.095 到 0.881、0.118 到 0.487、0.067 到 0.420（逐例读数，未认证，
n=24 上的个别事件），近贪心又炸两条，两者都指向退化性重复这一个失败模式。
均值判定说无法区分，是因为少数灾难样本把方差撑爆了（±0.2281）。
**尾部是真的，只是这个样本量证明不了。**

### 7.4 文本那三个值没有证据，是继承来的

上面扫的全是音频轴。`temperature 0.7 / top_p 0.9` 是契约默认值，从没扫过。
它们不是「测出来最优」，是「没人测过」。要调就调，
但请把改动前后的效果测出来告诉我们，别当成我们背书过的推荐值。

### 7.5 采样这条轴是活的，只是效应比我们的分辨力小

诊断过采样器面对的分布（官方权重，40 条）：77.8% 的音频码与贪心一致，
按码本拆开是 86.8%（码本 0，语义）递减到 70.8%（码本 7，最细声学）。
约五分之一的码不是贪心选择，所以这条轴没关死；
上面那些无法区分是功效问题，不是「采样无效」。
谁要主张这条轴上有 0.01 量级的收益，得先把样本量提一个数量级。

## 8. 出错时

| 状态 | 含义 | 你该做什么 |
| --- | --- | --- |
| 503 | 没配引擎，或那一段还没接上 | 看 detail，它点名是哪个变量或哪一段 |
| 400 | 请求体没有音频 | 检查是否真的发了 PCM |
| WS `error` 帧 | 事件类型不认识，或缓冲区为空 | 看 `error.message` |

错误信息说明出了什么问题和怎么修，不含道歉也不含含糊措辞。
碰到看不懂的错误信息算我们的 bug，报给我们。

按症状排查见[运行手册](RUNBOOK.md)。

## 9. 现在能做和不能做

| | 状态 |
| --- | --- |
| 接口契约 | 冻结，可据此开工 |
| 桩服务 | 可跑，返回 503 或假数据视配置 |
| 级联的转写与出声 | 可跑真音频（出声需 `MINDSURF_TTS`：`edge` 托管、`voxcpm` 本地） |
| 级联的整轮对话 | 指 `MINDSURF_THINKER` 到成品即可 |
| 原生路径 | 整条链验收过。延迟是它的长处（首音 145 ± 4 ms、P95 189 ms），声音是它的短处，别默认切过来 |

**契约冻结后只增不改。** 确实要改会提前说，并给迁移路径——
你们和模型是并行开发的，一个字段挪位置，两个组各赔一天。
