# 能力边界：打断、情绪、音色克隆，模型侧到哪为止

写给要接线的人。这一页只说模型侧能做什么、做不到什么，以及做不到的原因是接线还是训练。
服务层实现不在这里，但每一条都指明模型侧的支持点在哪。

对着的是 KPI-3：「LLM 内部能同时处理文本 token 与音频 token，
支持语音打断、情绪控制、音色克隆」。

**一句话**：打断的执行做到了、判断没做；音色克隆认证优于上游，但 12 个音色只有 6 个能用；
情绪的能力存在，做不成旋钮。

数字取自 [`configs/release/headline_numbers.json`](../configs/release/headline_numbers.json)。

---

## 1. 语音打断

### 1.1 执行：闭环了，而且是分两件事证的

模型侧从一开始就没问题。`model_omni.py` 的 `stream_generate` 是生成器，
每步 yield 一次 `(ids, frame)`，停止生成只需要停止迭代，没有要清理的内部状态、
没有必须跑完的固定长度。

服务层原来打不断：生成跑在事件循环里，流式期间没人读 socket，
取消要排队等整轮说完。生成已挪进可取消的 task。

实测（`sft_merge`，原生路径，40 轮）：

| 量 | 线 | 实测 |
| --- | --- | --- |
| cancel 到 `response.done(cancelled)` | ≤ 200 ms | **P50 0.26 ms / P95 0.40 ms** |
| 取消后在途音频帧 | 附报 | 中位 0，最大 1 |

**过得离谱是要先怀疑仪器的。** 上面量的只是控制面，它排除不了「早确认、晚冲刷」：
服务先答停了，生成线程继续在卡上把整轮解完。这个项目正是栽在这个形状上过——
一个泄漏把首音从 145 ms 顶到 3356 ms，三天里两次被误诊为「环境太吵」。

所以直接量了活儿停没停：

```
完整回合墙钟       4953 ms
被取消回合墙钟      132 ms      占完整的 2.7%
取消瞬间 GPU  [41, 27, 27] %    0.5 秒后  [0, 0, 0] %
```

三条互不依赖的证据合起来才算过：控制面 0.26 ms、在途帧 ≤1、墙钟 2.7% 且 GPU 归零。

### 1.2 判断：没做，而且缺的是语料不是代码

能停不等于会判断该停。用户是不是插话了、什么时候该停，**我们这边没有任何东西在做**，
契约把端点决定交给了客户端。

同类系统的标准解是在骨干 LLM 最后一层后加一个分类头逐块预测状态。
我们的隐状态本来就在手上，接一个头即可，冻结 Thinker 的配方也原样适用。
**卡住的是语料**：要重叠音频加打断标注，我们手上两份语料都没有，
合成的重叠只等于 VAD，拿它训出来的是端点检测不是打断判断。

两条一并写明，免得被读成我们有的能力：

- **回合制，不是全双工。** 「自己一路、用户一路、没有说话人回合」的双流要重训整条链，
  明确不做。所以打断在这里的含义是「取消当前这一轮」，不是「一边听一边说」。
- **打断之后能不能接着聊，没测过。**

### 1.3 多轮：三轮之内不崩，上下文不是瓶颈

50 组对话 × 3 轮，第 2、3 轮全部是省略句（「那哈密瓜呢」），不看历史答不了；
模型自己的回复喂回去当历史。

| 轮 | 用上历史 | 答得上 | 空 | 循环 |
| --- | ---: | ---: | ---: | ---: |
| 1 | | 42% | 0 | 0 |
| 2 | 82% | 24% | 0 | 0 |
| 3 | 82% | 14% | 0 | 0 |

给后端的三条：三轮之内不会塌，也不需要压缩历史（上下文利用率 82% 且不随深度衰减）；
但答得上的比例随深度掉，而第 2、3 轮的问题是刻意设计的省略句、本来就更难，
所以 42% 到 24% 里难度和深度分不开，**24% 到 14% 才是干净的同类比较**；
**只测到三轮**，十轮以上没测，那时上下文长度才可能真的成为问题。

### 1.4 打断为什么要紧：回复有多长

608 条探针上重算，成品对父模型：

| | `sft_merge` | 父 `sft_graft_frozen` |
| --- | ---: | ---: |
| 中位回复 | 55 字 / 11.8 秒 | 26.0 秒 |
| 占用比（模型说话秒数 ÷ 用户说话秒数） | 6.2× | 13.7× |
| 5 秒时还没说完 | 81% | 93% |

秒数由字数按实测语速 4.67 字/秒折算，**是估计不是直接测量**。

**试过用系统提示压短，是负增益**：中位 30.0 到 30.9 秒纹丝不动，
而编造从 13% 涨到 42%。这个规模的模型指令跟随太弱，长度只能靠训练改，
`sft_merge` 那 11.8 秒是训出来的不是提示出来的。

## 2. 音色克隆

### 2.1 模型侧支持点

```python
# model_omni.py
def stream_generate(self, input_ids, ..., **args):
    spk_emb   = args.get('spk_emb',   None)   # (1, 192) CAM++ 向量
    ref_codes = args.get('ref_codes', None)   # (1, 8, N) 参考 Mimi 码带
```

参考码右对齐填进 assistant 起点之前的音频缓冲区，说话人向量占它前面一个位置。
**换音色只换这两个输入，Talker 权重一个不动**，加一个音色不需要训练。

现成音色包：`model/speaker/voices.pt` 5 个内置（dylan、eric、serena、uncle_fu、vivian）
加 `voices_unseen.pt` 7 个留出（arthur、chelsie、cherry、ethan、jennifer、momo、moon），
每个是 `{ref_codes: (8, N), spk_emb: (192,)}`，参考时长 5.1 到 9.4 秒。

### 2.2 读数之前先知道天花板

把存好的参考码解码回音频再重抽 CAM++，和存好的向量算余弦只有 **0.8409**
（0.7888 到 0.8964）。差的那 0.16 是 Mimi 8 码本 12.5 Hz 对说话人身份的损耗，
**每条生成音频都要付**。所以上游报的 seen 0.6472 / unseen 0.5654 应该读成
编解码器允许范围的 76% / 68%，不是「离 1.0 还差一大半」。

### 2.3 量出来的

成品对父模型（12 音色 × 20 句，逐条配对）：seen **0.6487** 对 0.6470、
unseen **0.6044** 对 0.6054，噪声底 ±0.015，不劣化。

更早那一轮对上游官方发布权重：`improved (+0.0354, ±0.0152, n=240)`，
**12 个音色逐个比全赢**。尺子先过了效度检查——官方臂复现上游报的 unseen 0.5633 对 0.5654。

### 2.4 接线要照这张表，不要照一个数

上面那把尺子量的是「离自己多近」，它答不了「听起来还是不是这个人」。
把每条生成音频对 12 个音色的向量逐一比、取最近的那个：

| 档 | 音色 | rank-1 | 能给的保证 |
| --- | --- | ---: | --- |
| 认得出 | arthur、serena、eric、uncle_fu、dylan、moon | 19–20/20 | 换到这几个，听感上是换了人 |
| 边缘 | vivian、jennifer | 8–15/20 | 不保证，要用先自己听 |
| **认不出** | cherry、ethan、chelsie、momo | ≤ 2/20 | **别当独立音色投放**，它们塌向 serena 和 moon |

上限臂（参考码解码回音频）12/12 全认对，所以这不是判官分不开，**是生成侧带的身份不够**。

**给的是名单不是一个数。** 合成一个「60%」去比大小没有判定资格：
按音色重抽的噪声底 ±0.2312，分辨得了 0.69 而我们关心 0.10；
提高音色数也救不了——要够格约需 580 个音色。

### 2.5 这个能力的价钱

买下它的是 A2A 那三段训练。同一段在散文损失上付了 **+1.52 nat**，
在对话质量上也付了——盲评三维度多数票输给 T2A 产物 74%，两个中立参照集一致
（+0.7702 / +1.5599 nat）。在这个产品里这笔交易划算，克隆是 KPI-3 的一项，
**但价格两边都有数**。

级联可以规避这笔代价：它不用 Talker，只拿 Thinker 生成文本再交给合成器念。

### 2.6 要量在 A2A 产物上

`sft_a2a` 的列里有 `ref_audios` 和 `spk_emb`，`sft_t2a` 里没有，
所以 T2A 阶段从没在那个位置见过说话人 token。不是理论——
同一套代码路径、同样 12 音色 × 20 句：官方 240/240、A2A 成品 240/240、
**T2A 产物 3/240**（237 条 `no complete frames`）。

## 3. 情绪控制

**能力存在，旋钮做不出来。** 这一节说清楚这两半各自的证据。

### 3.1 能力那半是真的

同一说话人、平静与激动两条参考，喂给验收 checkpoint，12 条固定文本配对：

| 输出（excited − calm） | 均值 | 为正的 |
| --- | ---: | ---: |
| F0 中位 | **+54.7 Hz** | **12/12** |
| F0 起伏（IQR） | +19.7 | 11/12 |
| 同文本时长 | −3.3 s（更快） | 0/12 |

零训练。可懂度做了粗大缺陷筛（两臂 CER 0.045 / 0.039，n=12 分辨不了细差，
只保证没把话说坏，不作判定）。**给模型一条带情绪的参考，输出就带情绪。**

### 3.2 旋钮那半：三条路都走死了

**第一条，改造参考音频。** 用信号处理把中性参考变成情绪参考——
改造后的参考自己就听不清了，20 个变体 15 个 CER > 0.6、4 个转写全空。
伤在相位声码器不在移调，所以保共振峰校正修不了。

**第二条，向量算术。** 先把通路拆开了：只换 `spk_emb` 效应全在
（F0 `improved +68.8, ±26.2`），只换 `ref_codes` 什么也没有
（`indistinguishable -0.8, ±12.6`）。**能调情绪的输入只有说话人向量，
而它同时就是身份。** 取 Δ = 两条参考的向量差，加到任意音色上，
情绪确实出来了（F0 `improved +12.05, ±7.55, n=240`）、话也没说坏（CER 配对无法区分），
**但身份掉出去了**：12 选 1 认人从基线 0.6000 掉到 α=0.35 的 0.5167、α=0.50 的 0.4458，
裕度配对两个都 `regressed`。仪器先验过——上限臂 12/12、阳性对照 α=1.0 从 0.9875 掉到 0.5625。

**第三条，条件化重训。** 拿 emotion2vec 给 414,024 条语料标情绪，
每行 user 侧加一句「请用○○的语气回答」，跑一轮 A2A。成品 `sft_emo_768.pth`。
CER 0.0902 过、Thinker 91/91 逐位不变过，**主判据 F0 零效应**——
四条情绪臂对 neutral 全部 `indistinguishable`，差 +0.6 到 +1.2 Hz 而噪声底 ±3.7 到 4.7。
**对照臂先过了，所以这是真零不是读不出。**

后来知道了为什么：**标签不可信**。四个人盲听核标签，
人对 `emotion2vec` 标签一致率 **31–42%**，人对人 **41–65%**。
两个数都低说明任务本来就难；人彼此对得上、却都对不上标签，
那是标签系统性偏离人耳。那一夜的卡等于教模型一批约 64% 错误的指令-韵律对。

### 3.3 所以接线怎么办

**级联那条路照旧可用**：`EDGE_PROSODY` / `EMOTION_INSTRUCTIONS` 三档，
它管的是措辞加合成器韵律。

**原生这条路能给的只有一件**：自备一条该音色带情绪的**真实录音**当参考，
走和音色同一条 `/v1/voices` 通路，不需要新的模型接口。
效果是 §3.1 那个 12/12，但它换的是参考不是旋钮——
**你没法在不换人的前提下把「开心」调大一点**。

**情绪必须走独立字段，不要拼进文本。** 指令前缀被合成器念出来这件事姊妹项目踩过，
`tts.py` 的 `instruction_leaked()` / `screen_batch()` 就是为它写的。

情绪与音色纠缠是学界的公开问题，解法要独立编码器加解耦损失再重训，
本项目一开始就排除了架构改动。

## 4. 一个部署时会咬人的形状问题

**嫁接体的两半形状不同**：我们的 Thinker 是 FFN 3584 / 8 KV 头，
上游的 Talker 是 FFN 2432 / 4 KV 头，一个 checkpoint 里同时装着两者。

服务原来加载不了它：`load_omni` 无条件把两半都按 3584/8 建，
起服务时 20 个 size mismatch 直接崩——我们花三轮训出来、且过了验收的那个模型，
我们自己的服务路径装不进去。

**已修**：加载器从 checkpoint 里读形状，不从配置取。理由与训练侧那道守卫相同：
配置能被设错，而设错的后果不是崩，是**一半 Talker 停在随机初始化上照样吐码，
解出来是噪声**。两条拒绝一并加上——Talker 宽度不认识就拒绝（不猜），
纯文本 checkpoint 在加载时就点名（不等到第一个 missing key）。

**对你们的意义**：换 checkpoint 不需要改配置，形状是读出来的。
