每条的 `source` 指向 `artifacts/` 里产出它的逐条读数。

## 1. 模型

139.08M 参数装在一个文件里，两半来历不同：

| | 参数量 | 来历 | 形状 |
| --- | ---: | --- | --- |
| Thinker（文本） | 89,864,448 | 我们自己的文本基座 | MHA、FFN 3584 |
| Talker（语音） | 47,050,754 | 上游 MiniMind-O 发布权重 | GQA 4 头、FFN 2432 |

两半之和是 136.92M，和 139.08M 差的那 2.17M 是把两半接起来的部分，不计入任何一半。

加载器必须从权重里读形状而不是从配置取。
配置能被设错，而设错的后果是一半 Talker 停在随机初始化上照样吐码，解出来是噪声。

Talker 不接 Thinker 的最后一层，接第 3 层（`num_hidden_layers // 2 - 1`）。

两头都不合适。最后一层的输出直接送进 LM head 算 logits，它是为「下一个 token 是什么」
特化过的表示，而 Talker 要的是这句话在说什么。最前面的 embedding 层则还没过注意力，
上下文没参与，不知道这个词在这句话里是什么意思。所以要取中间的某一层。

具体取第几层是上游定的，我们沿用，没做消融，所以「第 3 层是不是最好的那层」未知。

音频侧是 Mimi，8 个码本、12.5 Hz。

## 2. 训练过程

```text
文本基座
   │  ① 接入：重命名 + 等价性检查
   ▼
llm_768_mindsurf.pth ────┐
                         │  ② 嫁接：换上上游的 Talker
上游 sft_omni_768.pth ───┘
   ▼
graft_ours_thinker_up_talker_768.pth
   │  ③ T2A：1 epoch @ 5e-5
   ▼
t2a_graft.pth
   │  ④ A2A：full 5e-5 × 3 → tail 5e-6 × 1，seq 1024、bs 10
   ▼
sft_graft_frozen.pth
   │  ⑤ 两次 DPO 的权重差相加
   ▼
sft_merge_768.pth   ← 成品
```

### 2.1 接入是重命名，不是重实现

我们的基座和 MiniMind 的模型类本来就是同一套结构，参数名也已经对齐，
`load_state_dict` 零 missing、零 unexpected。只有两个值必须显式传，
否则上游默认值会悄悄建一个更小的模型再拒绝我们的权重：
`num_key_value_heads` 传 8（我们是 MHA 不是 GQA）、`intermediate_size` 传 3584。

`gate_proj` 与 `up_proj` 二者注意不要接反，接反了模型照样跑，只是变差。

### 2.2 嫁接：为什么不自己训 Talker

我们训过自己的 Talker，它能说话，但文本能力降低：跑完 A2A 之后，
留出文本集上每个 token 的交叉熵从 3.1993 涨到 4.7173，高了 1.52 nat，
换成困惑度是四倍半。盲评三维度多数票输给纯文本产物 74%，两个中立参照集一致。

换成上游已经训好的 Talker 配我们自己的 Thinker，T2A 一轮之后 CER 0.0819、静音 0/160。
和上游官方发布的权重念同一批 160 句、逐句配对比较，差值落在噪声底以内，
判定是「无法区分」。

这个项目所有比较只有三种结论：改善、劣化、无法区分，
落在噪声内的差异不允许报方向。

### 2.3 A2A

A2A 在上游是三个阶段跑完的，脚本里的名字即 `a2a_proj`、`a2a_full`、`a2a_tail`：

| 阶段 | 训什么 | 学习率 × 轮数 |
| --- | --- | --- |
| `a2a_proj` | 只训 `audio_proj`，其余冻住 | 5e-4 × 1 |
| `a2a_full` | 全部解冻 | 5e-5 × 3 |
| `a2a_tail` | 全部，小步收尾 | 5e-6 × 1 |

这套配方是给从零开始的模型设计的，而我们是把一个半成品接进去，所以做了一些改动。

**不跑 `a2a_proj`**（脚本里 `SKIP_PROJ=1`）。这个阶段是为一种特定情形设的：
投影层刚初始化、还是随机的，此时若直接解冻全部，
反向传播会经过这个瞎猜的投影把误差算到 Thinker 头上，
把已经训好的语言权重带偏。所以要先单独把它对齐。

我们不在那种情形里。嫁接体的 `audio_proj` 取自已经跑过 A2A 的模型，不是随机的。

相反，如果给一个已经到位的投影再来一个 5e-4 的步长（`a2a_full` 用的是 5e-5，
小一个数量级），更可能把它迈过头而不是训得更好。
这一条是推断，未跑对比实验。

**把 Thinker 冻住。** A2A 的训练目标是音频，但实测后发现它对 Thinker 的位移
比对 Talker 还大 2.1 倍。所以最后一轮只训 Talker 和 `audio_proj`。
结果是 Thinker 91 个张量逐位不变，而克隆与语音的配对判定仍然是
`indistinguishable`：文本能力和语音能力均无劣化。
所以文本那半从此不再被 A2A 碰，原生路径和级联路径可以共用同一个 checkpoint，不用各留一份。

**序列长度改回 1024。** 那是上游的值，我们此前用 640/768。
音频目标很长（Mimi 每秒 12.5 帧），640 的窗口装不下整条，
尾部的目标码直接落在窗口外、不进损失，模型从没见过句子无法收尾。
而此做法不报错，只是让指标差一点。

### 2.4 两次 DPO，然后把权重差加起来

成品不是重训出来的，是 `sft_graft_frozen` 加两个 Δ，一个负责质量一个负责减少回复所需时间。

两个 Δ 的余弦是 +0.1329，近乎正交，相加之后两个效应都保住了。
中位回复降到 11.8 秒，而语音那半（104 个张量）与父模型逐位相同。

试过用系统提示压短，是负增益：中位 30.0 秒到 30.9 秒纹丝不动，
编造从 13% 涨到 42%。这个规模的模型指令跟随太弱，长度只能靠训练改。

## 2.5 润色器：第二阶段产品用的那个

第四次会议之后产品改成听写，多出来一件活：把转写里的口语词删掉。
润色器是从成品 `sft_merge_768.pth` 再微调出来的，不是新训一个基座。
配方、消融和每一次改动的读数都在 `artifacts/polish_train/` 和
`artifacts/polish-eval-*.json`，下面只写结论和它们是怎么来的。

先量了这件活有多大再动手，量完取消了其中一件半。
原计划是「纠错 + 删口语词 + 断句」三件。实测：转写 160 条全部自带标点，
断句这一格划掉（原以为要教的事不存在）；干净臂折叠字错率 0.0063 ± 0.0021，
纠错买不到多少。润色的编辑预算是 762 插入对 96 替换——**89% 是删，不是改**。
那 0.63% 的错形状单一（它→他、地→的、得→的，全是同音字），随删一起学到，
不单独设判据。

训练数据走真链路造。 3169 对：往干净文本里注入口语词 → edge-tts 念出来 →
SenseVoice 听回来。15% 不注入，让「什么都不改」也是一个合法答案。
从 `sft_merge_768.pth` 训 2 epoch。

**关键的一步不是训练，是换输出形态。** 自由生成那一版四条判据只过一条，
字错率 0.0930，尾巴的形状是「回去答题 / 半路停 / 接着编」。
把解码限制成「输出必须是转写的子序列」之后，编造这一格结构性地过了：
输出的每个字都来自转写，模型加不了字。字错率同时掉到 0.0416。
代价是替换类修正结构上做不了，那类错只占 0.63%，知情取舍。

第二条臂是一个逐字标注器，和生成式并行跑，两条结果按 veto 合并。
生成式擅长口语词，标注器擅长重复，两者的强项不重合。
合并那一层后来又改了几次，每次都是因为把服务当用户用的时候看见了输出里的字：
重复只掉一份不掉两份、删除不许切穿词、重复串的切口对齐到整份、
一份口吃不许被整词约束还回去、相邻重复的整词两条臂都没提时也删一份。
每一条的理由和读数写在 `src/mindsurf_omni/service/polish.py` 对应函数的 docstring 里，
测试在 `tests/test_merge_polish_arms.py`。

踩过的坑值得记两条。 第一轮训练器漏了结束符，模型没被教过在哪停，
修完字错率从 0.1297 降到 0.0930。关掉重复惩罚字错率还能再降到 0.0742，
但口语词清除跌到 0.886——这个旋钮在这任务上没有免费午餐。

## 3. 注意事项

**训练必须走 `scripts/train_omni.py`。** 直接调上游脚本会用它的默认形状
（GQA 4 头、FFN 1536），和我们的基座对不上，`strict=False` 把 40 个张量默默跳过
留在随机初始化，报 113.13M 而不是 152.06M，然后训出一个基座几乎没参与的模型。
（这两个数都是自训的 Talker 那一轮的可训练参数量，不是成品的 139.08M。
成品的 Talker 来自嫁接，比自训的那个小。）
现在的启动器把形状钉死，Thinker 参数不等于 89,864,448 就拒绝启动。

**上游代码一行不改，全靠启动器在运行时打补丁。** 上游的训练逻辑正是要保持不变的
部分，改了它，结果有差异时就分不清是谁造成的。代价是补丁依赖上游内部结构，
上游改了会静默失效，所以在启动器里添加了参数量检查功能。

**loss 看起来涨了先别信，日志不动也别急。** 行组 shuffle 让每个位置看到不同数据，
所以单看一段 loss 曲线得不出结论，用 `watch_training.py`，它按 step 对齐并算出
这批数据本身的测量误差。日志半天不动通常是 stdout 缓冲不是卡住，
看 checkpoint 文件的修改时间和进程的 CPU 时间就知道，下次启动加 `PYTHONUNBUFFERED=1`。

**数据是按行组shuffle的，不是全局shuffle。** 上游数据集把整张 parquet 读进内存，
full 数据在 23 GB 机器上装不下。同一行组的样本在一个 epoch 内总是挨着，这里能接受是因为上游文件已经打散过。

**`artifacts/polish_train/*.jsonl` 是在读回链还没接采样率的时候建的。**
润色的训练对是「原文 → 注口语词 → 合成 → 识别回来」这样造的，
`scripts/build_polish_pairs.py` 往识别器传的是 24 kHz。这个参数在 8370609 之前
是死的（识别器不看它，一律当 16k 处理），之后是活的。所以现在重跑同一个脚本
产出的不是同一批数据，落盘的这批也不能拿当前代码复现。
重训之前要么重建一批，要么明确按现在这批算——**两条别混着用**。

## 4. 结果与边界

### 听写（第二阶段的产品）

986 条留出集，RTX 4090 上的服务真路径，标注器阈值 0.4。
这几条线是算法侧自拟的工作标尺，不是小组 OKR 的验收线。

| | 不润色 | 只有生成式 | **产品** | 只能删的最好结果 | 自拟线 | 重抽里落在线内侧 |
| --- | ---: | ---: | ---: | ---: | --- | --- |
| 字错率 | 0.1060 | 0.0435 | **0.0269** | 0.0156 | ≤ 0.02 | 0% |
| 口语词清除 | 0 | 0.8643 | **0.9722** | 0.9966 | ≥ 0.90 | 100% |
| 内容保留 | 0.9868 | 0.9726 | **0.9803** | 0.9866 | ≥ 0.98 | 62% |
| 编造 | 0.1054 | 0.0287 | **0.0199** | 0.0150 | ≤ 0.02 | 54% |
| 空输出 | 0 | 0 | **0** | 0 | 0 | — |

「只能删的最好结果」是给定这份转写、只允许删字所能达到的最好成绩，
它是 0.0156，在 0.02 线以下。所以判据不是不可达，产品离它还差 0.0113。

字错率没过的构成：0.0127 是识别器听错的字（只能删，改不了），
0.0041 是把语料自己的口语词也删了（对听写产品是对的）。
两项相加 0.0168 是地板。

### 语音助手（已验证，按数据选择不投产）

| | 值 | 参照 |
| --- | ---: | --- |
| 参数量 | 139.08M | 上限 200M |
| 首个音频 | 145.1 ms ± 4.1 | 预算 3000 ms |
| 打断执行（取消到停） | 0.26 ms（P50） | 预算 200 ms |
| 人耳 MOS（四人盲听） | 2.738 | 上游官方发布权重 2.738 |
| 中位回复时长 | 11.8 秒 | 父模型 26.0 秒 |

三条边界：

**一、测不出来「把回复变短」没有顺带弄坏对话能力**
使用方法：拿一批别人写的回复当参照，看模型觉得它们有多像自己会说的话
（指标叫 `chat_nll`）。问题是**参照回复是有长度的**。模型变短之后，
它觉得那些较长的参照没那么像自己了，分数就变差——
但这是「长度口味变了」，不是「对话变差了」。两件事混在同一个数里，分不开。

以下是尝试的改进，均无疾而终：

| 办法 | 为什么不行 |
| --- | --- |
| 直接用参照集比 | 两批参照对「谁更好」只有 20.3% 给出一致答案，而分差和参照长度的相关系数是 +0.601。它在量长度 |
| 按参照长度分层再比 | 控住长度之后一致性掉到 1.9%，信号全没了 |
| 改看「答得上率」 | 拿一次已知的质量崩坏去试它，它没读出来（+0.0872 落在 ±0.1061 噪声里）。|
| 用长度配平过的参照集 | 一致性升到 94.9%，原毛病没了。但那批参照本身偏短，模型变短之后自然更配它，分不开「答得更好」和「长度刚好对上」 |

原办法要够用，估算需要约 3600 条探针，我们只有608条。

成品 `sft_merge` 把中位回复从 26.0 秒压到 11.8 秒，但是该轴认证不通过。
另一个候选 `sft_dpo2` 没改长度，这一轴认证过、五条判据全过，代价是回复要念 24.2 秒。
从产品设计上讲最终选择前者。

需要补充说明的是，测不了的只是改变长度的干预。对不改长度的干预，`chat_nll` 原来那把
尺子本身就没有这个混淆——`sft_dpo2` 就是这么过的：两批中立参照一致率 58.9%（够格），
两条判词都是无法区分。

**二、情绪能力存在，但做不到「只动情绪、不动身份」**
给模型一条带情绪的参考，输出就带情绪（F0 +54.7 Hz、12 个音色全为正、零训练）。
但能调情绪的输入只有说话人向量，而它同时就是身份。
那种「音色不变、开心程度连续可调」的滑块做不出来。
因此能做出几种情绪，等价于你手上有几条参考录音。
而且具有局限性：每条参考是一个固定的点，点与点之间没有值，没办法做到连续可调。

试过用向量插值把它变连续（α=0.35、0.50 两档），情绪确实连续了，
但 12 选 1 认人从 0.6000 掉到 0.4458，说明目前没办法在情绪连续的情况下保住身份不变。

**三、打断做到了执行，没做到判断。**
调用方说停，模型就真停。但「什么时候该停」没做。

要训这个，需要一批「模型正在说话、用户同时开口」的录音，而且标明每次重叠是不是真的想打断。
用户开口也可能只是「嗯嗯」这种附和，或者背景有别人在说话。
我们用的两份训练语料既没有重叠音频，也没有打断标注。

自己拼一批出来没用：把两段无关的录音混在一起，附和和抢话长得一模一样，
唯一能学到的规律是「有没有人声」。
而这种判断一个语音活动检测器（VAD）就能完成，不需要训练模型。

## 5. 复现与证据

```bash
# 基座接入（退出码非零）
python scripts/convert_base_to_minimind.py --source <HF model dir> \
  --minimind-root <minimind-o checkout> --output out/llm_768_mindsurf.pth

# 训练：走这个启动器，不要直接调上游脚本
python scripts/train_omni.py --data_path <parquet> ...

# 看进度、验交付
python scripts/watch_training.py --log <训练日志> --metric audio
python scripts/verify_delivery.py
```

每个数字的逐条读数在 `artifacts/`，由 `headline_numbers.json` 的 `source` 指过去。
每份 JSON 都记录判词、噪声底、样本量、判官身份和种子。
根目录是单次测量，子目录是成组的一批
（`merge/` 成品、`blind608/` 608 条盲评、`dpo4/` `dpo5/` 各轮 DPO、`listening_*/` 三个盲听包）。

探针集在 `configs/`：`speech_probes_zh_v1.jsonl` 和 `talker_texts_zh_v1.jsonl`
各 160 条固定文本，`blind_probes_zh_v1.jsonl` 608 条对话盲评（原来 158 条不够用，
扩到 608 才够分辨主判据）

带 `.provenance.json` 的参照集要连出处一起读。参照集是拿来比「谁的对话建模更好」的，
而如果它恰好是被比较的某个 checkpoint 写的，那个 checkpoint 必赢,因为那本来就是它的输出。
这件事发生过：`talker_texts_zh_v1.jsonl` 那 160 句后来被发现是 `sft_mindsurf_768`
生成的，而它当时正在被比较。之后每个参照集才配上出处记录，写明作者是谁。
