# 训练说明

识别器用的是上游的SenseVoice-Small，朗读用的是 edge-tts，这两个我们都没训过，不在这份说明里。

---

## 1. 模型

润色器 89,864,448 参数，是我们自己的文本基座（MHA、FFN 3584、词表 6400）。
它有两条并行的「臂」：一个生成式模型，一个逐字打分的标注器，都从这个基座
微调出来，标注器只是多了一个二分类头。

加载权重时，形状从权重文件里读，不从配置里取。原因是配置能被设
错，而设错的后果很隐蔽：PyTorch 的 `strict=False` 会把对不上的张量静默跳过，
留在随机初始化上，模型照样出结果，只是差。所以加载器把形状和参数量绑在一起
检查：Thinker 参数量不等于 89,864,448 就直接拒绝加载。

直接调上游训练脚本会用它的默认形状（GQA 4 头、FFN 1536），
和我们的基座对不上，40 个张量被跳过，参数量报 113.13M 而不是
152.06M，最后训出一个基座几乎没参与的模型。

---

## 2. 训练链路

3169 对训练样本：

```text
干净文本 ─► 注入口语词 ─► edge-tts 念出来 ─► SenseVoice 听回来 ─► （转写, 目标）
```

不直接拿文本构造是因为中间「念出来、听回来」那两步，会让训练数据带上
识别器真实的听错和标点习惯。

另外留 15% 的样本不注入任何口语词，让「什么都不删」也是一个合法答案。不留的
话，模型学到的是「每句话都得删点什么」，干净的句子也会被啃掉脑子喵。

`src/mindsurf_omni/data/synthesis.py` 是造数据的工具，不是服务的一个环节。

---

## 3. 输出形态的迭代

第一版让模型自由生成润色结果，四条判据只过了一条。字错率 0.0930，失败的样子
五花八门：把润色任务当成问题去回答、生成到一半停住、顺着转写往下编。

后来把解码改成**输出必须是转写的子序列**。模型每一步只能选「保留转写的下一个
字」或「跳过它」，别的字一概不许输出。这一改，输出里的每个字都来自转写，
编造在结构上就不存在了。字错率同时从 0.0930 降到 0.0416。

代价是替换类的修正做不了：识别器把「它」听成「他」，润色器无能为力。
那类错只占 0.63%，天下没有免费的午餐喵（也许有早餐，因为无法起床吃早餐）。

### 第二条臂

生成式模型删口语词很准，删重复不够准。所以又训了一个逐字标注器和它并行跑，
两条结果按「veto」合并：默认两边都说删才删，只有两类例外（词表里的口语词、
紧挨着的整段重复），这两类只要一边认出来就删。生成式擅长前者，标注器擅长后者，
强项刚好互补。

合并那一层后来改过好几次，每一次都是在服务器跑全量测试时，亲眼看见输出
里少了或多了字：重复要只删一份不能删两份、删除不许把一个词切成两半、口吃的
那一份不许被整词规则还回去……每一条的理由和读数都写在
`src/mindsurf_omni/service/polish.py` 对应函数的注释里。

| 口语词清除 | 0 | 0.8621 | **0.9606** | ≥ 0.90 | 100% |

过线与否按重抽比例读，不按点估计：把行反复重抽 4000 次，每次重算一遍指标，
看它有多少次仍落在线内侧。

### 230 段真人长口述

留出集的口语词是我们自己插的，模型考自己人出的题，成绩可能虚高。所以又拿
230 段真人长口述（RAMC）量了一遍。这批没有人工标签，判据有两类：

- 「该删的删了没有」只认最没有争议的两类：嗯/呃（人工语料里 98% 被标成
  口语词），和紧挨着的整段重复。
- 计数「没有任何理由支持的删除」：删掉的字既不在口语词表里、也不属于任何重复。

尺子本身先受检：拿 CS2W 的人工逐字标签当真值，这套探测器按处算和人的一致率
0.9490（嗯/呃 896/911，重复 1506/1620）。

## 5. 各种尝试

山重水复疑无路，柳暗花明又一村。

### 按真人分布重造重复的形状——没用

推理链看起来很顺：训练数据里重复的形状和真人差很远（单字重复占 10%，真人
语料里占 58%；中间隔开的占 33%，真人占 49%），而模型恰好在单字重复上召回
最低。所以形状是原因？

按真人分布重写注入器，重造 3172 对，走完全链路，同基座同超参训一条；
再训一条只换回旧数据当对照。结果：新形状 0.595，旧形状 0.604。配对自助 2000 次，
差值 −0.0096，95% 区间 [−0.0273, +0.0067]，跨零，分不出高下。

### 给标点加解码偏置？不值得

只能删的约束顺带把标点也锁死了。放开一道门（只允许纯标点的 token 进来），
再给它们的 logit 加偏置：

| 偏置 | micro_F1 | 插入次数 | 正文字数 |
| ---: | ---: | ---: | ---: |
| 地板（照抄转写的标点） | 0.3641 | — | — |
| 0.0 | 0.3780 | 1012 | 16120 |
| **1.0** | **0.3800** | 2773 | 16001 |
| 2.0 | 0.3720 | 5057 | 15863 |
| 8.0 | 0.3249 | 50061 | 13585 |

偏置开大了标点会抢正文的位置：8.0 时正文少了 16%，而跳过的内容字再也回不来。
所以`punctuation_bias` 默认 0.0，代码留着不启用。

### 长口述的切法

| | 按句切 | 160 打包 |
| --- | ---: | ---: |
| 嗯/呃 召回 | 0.9891 | 0.9902 |
| 重复召回 | **0.8970** | 0.8835 |
| 误删/千字 | 13.64 | **11.91** |
| 退回没润色的字 | **722** | 3578 |
| 墙钟 | **90 s** | 105 s |

差距是口语词 1 处、重复 5 处、误删 43 字，这个规模上分不出好坏。最后改成
按句切，理由：代码少一层、快 14%、因超长而退回原文的字少五倍。

注意事项：完全不切的话，73.6% 的字压根没被润色。
超过约400 token 的单条输入，这个模型会直接收尾不回答。

160 字以内整条送的闸保留，那一半有 986 条留出集支持（中位 43 字）：整条送
召回 0.3829、精确 0.8401，按句切是 0.3571 / 0.8197。

闸位本身也量了。以前写「没有样本落在线附近」，那是只翻了留出集——它最长
170 字，只有 16 条过闸。而 `pairs_long` 的 val 有 143 条落在 160 到 300 字，
这道闸一直可以量，只是没人拿这份数据量过。230 条真人长口述，七档：

| 闸位 | 嗯/呃 召回 | 重复召回 | 误删/千字 | 退回没润色的字 | 停住的片 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 80 | 0.9902 | 0.8970 | 13.67 | 0.8% | 2 |
| 120 | 0.9902 | 0.8970 | 13.66 | 0.8% | 2 |
| **160（现在）** | 0.9891 | 0.8970 | 13.64 | 1.0% | 3 |
| 200 | 0.9869 | 0.8943 | 13.63 | 2.1% | 7 |
| 240 | 0.9869 | 0.8916 | 13.74 | 6.9% | 22 |
| 320 | 0.9869 | 0.8889 | 11.40 | 27.7% | 76 |
| 不切 | 0.9945 | 0.8591 | 5.80 | **73.6%** | 108 |

80 到 160 之间三个判据分不出差别：召回差 0.0011，重复完全相同，误删差
0.03/千字。160 往上开始塌，200 就有 7 片停住。所以 160 站得住，但它在安全区的
**上边缘而不是中间**，没有余量——想加余量往下调是免费的，往上调不行。

最后一行是这张表最值得看的：不切的口语词召回最高、误删最低，看着全表最好，
而它 73.6% 的字压根没被润色、16 片直接答空。少删的切法在只看删除质量的判据下
天生得分高，这就是前面那把偏了的尺子读出「越长越好」的机制。

顺带一条命名：`TRAINED_LENGTH` 这个名字名不副实。160 来自
`build_polish_holdout_pool.py` 的 `LONGEST`，是造训练对时把长文本丢掉的截断线，
不是模型能力的边界。

### 两条臂怎么合并

| 合并 | 嗯/呃 | 重复 | 误删/千字 | 否定词存活 |
| --- | ---: | ---: | ---: | ---: |
| **veto** | 0.9902 | 0.8889 | **11.57** | **0.9982** |
| union | 0.9902 | **0.9160** | 142.62 | 0.9493 |
| intersection | 0.7738 | 0.6016 | 11.40 | 0.9982 |

union 把重复召回买上去 0.027，代价是误删翻 12 倍，而且 230 句里有 34 句的
否定词被删掉——「没去」变成「去」，意思反了。留 veto。

### 在解码上加删除偏置——不需要

量了模型在每个决策点上的真实倾向：在必须选「保留下一个字」还是「跳过它」的
那一步，生成式模型对口语词只有 33% 的情况本来就想删（logit 差中位 −1.123），
对重复是 59%（+1.290）。看着像加个偏置就能捞一把，但两条臂合并后已经是
0.9902 / 0.8889 了，标注器已经把生成式的短板补掉。

## 6. 复现与证据

```bash

python scripts/inject_fillers.py --help

# 训练两条臂
python scripts/train_polish.py --help
python scripts/train_polish_tagger.py --help

# 量：986 条留出集
python scripts/measure_polish_service.py --help

# 量：230 段真长口述，不需要人工标签的判据

  --calibrate artifacts/polish_train/pairs_cs2w.jsonl   # 先验尺子再用尺子

python scripts/verify_delivery.py
```

的 `source` 字段指过去。每份 JSON 都记着判词、噪声底、样本量和种子。
